# Teardown Annotator 标注手册

面向每天标注 6 小时的人。全文假设你在 Windows 上、数据盘是 `D:`、原始数据盘 `F:` 只读。

---

## 1. 启动

```bat
rem 接着上次的机器和帧继续；也可以显式指定
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang --desktop 13 --view scan --step 42
```

- 只有 `--annotator` 必填（它也是锁的持有人）。`--desktop` / `--view` / `--step` 省略时按
  `tda_app.ini` 记的**上次的机器、视图、步骤**打开；第一次用打开有帧的最小编号机器的 `scan`，落在**最后一张有图像的帧**（倒序标注从这里开始）。
- 启动时先取**单人锁**再打开数据库。别人正开着时会弹框写明持有人和时间，以退出码 3 退出，
  而数据库文件根本没有被打开过（只读了一次锁文件 `<db>.lock`）。
- SAM 在窗口显示**之后**才后台加载，第一帧 0.7 秒左右就能看到。没有模型（缺权重、没有 CUDA）只是 `S` / `X` 不可用，状态栏写明原因，别的功能照常。
- 窗口大小、面板布局、上次的机器/视图/步骤存在 `D:\DataSet\.cache\tda_app.ini`，不写注册表、不写 C 盘；日志在 `D:\DataSet\.cache\logs\tda_app.log`。

**关闭时**依次：停后台线程（SAM、差异图、模型加载）→ `session.save()` → `session.close()`
（等自己的复检线程收尾）→ 备份数据库到 `paths.yaml` 的 `backup_dir` 并校验非空 → 释放锁。
备份失败只在状态栏告警，不拦着你关窗口。还有**没提交的编辑**时先弹框问：提交 / 放弃 / 取消。

## 2. 三种模式

顶部标签页切换，中间区域跟着换。**复查模式下画布只读**：不接工具，点画布只提示
"按 R 返工"——复查模式里开始的编辑没法提交（Enter/Esc 属于标注模式）。

| 模式 | 中间显示 | 什么时候用 |
|---|---|---|
| **Steps（S1 步骤核对）** | 步骤表 + 实例表 + 约束图 | 核对步骤、动作、目标实例，拆分复合行，删没人引用的实例，补约束边（§5.6）。`Apply` 后会话在**同一帧**重开；有未保存修改时切走会先问一句。 |
| **Annotate（标注）** | 画布 | 主战场。倒序一帧一帧往前画。 |
| **Review（复查）** | 只读画布 + 右侧队列 | 冲突、待复查、缺形状、未解释差异。`Enter` 接受、`R` 返工、`K`/`N` 处理冲突。 |

## 3. 倒序标注一步的流程

标注方向和拆解方向相反：你从最后一帧往回走，也就是"把刚拆下来的零件一个个装回去"。
`PgDn` 是"前进"（k−1），`PgUp` 是后退。

**关键一点：任务卡说的永远是"你眼前这一帧要画什么"。**
站在第 j 帧时，卡片列的是 j+1 到 j 之间的变化 —— 在 j+1 已经拆下、在 j 还装在机箱里的零件，
所以每一条都可以**就在当前这张图上**画出来并提交。按住 `Tab` 闪回的就是 j+1，`Shift+Tab` 闪回
另一侧；差异图也是拿当前帧和 j+1 比的，高亮那块正是卡片让你画的零件。（若 j+1 在本视图缺帧会跳到再上一帧，状态栏会说明——这时卡片跨了不止一个动作。）

1. **看任务卡**（右上）。它由会话根据相邻两帧的状态差自动生成，每条写明要做什么：
   - ✚ `add_shape`：这个零件在 k−1 还在机箱里，要把它画回去；
   - ✂ `split_keyframe`：形状变了（盖子打开→关上、接头拔掉→插上），需要新的一版形状；
   - ≡ `state_only`：形状不变，只是状态变（螺丝拧松→拧紧），不用画；
   - ▭ `add_bench_box`：零件拆到台面上了，双击这条把框工具武装给它（不开编辑层）；没武装时
     `R` + 拖框只认**这一帧确实在台面上**的选中实例，换帧/视图/机器/模式/工具或 `Esc` 解除武装；
   - ⌫ `remove_bench_box`：零件回到机箱里了，它的台面框到此为止；
   - ✔ `confirm`：这一帧没什么可画的（重复帧、失败帧），一个键确认。
   已经做完的条目会被划掉，第一条没做的自动高亮。

2. **双击任务卡条目**开始编辑。它会把该实例当前的完整（amodal）形状读进编辑层，黄色高亮。

3. **画**。两条路，通常混着用：
   - **SAM**：按 `S` 用点提示。差异图把"变化最大、且没被别的条目解释掉"那块的外框自动喂给 SAM
     （点+框实测 IoU 0.76，只给一个点 0.24），画面上有虚线框标出用的是哪块。
   - **手改**：`B` 画笔、`E` 橡皮，`[` `]` 调笔刷大小（可长按；非美式键盘可能要配合右 Alt，
     按不出来就用 `?` 查键名）。`Shift+F` 填空洞、`Shift+D` 删小碎块，各算一次可撤销操作。
   - **旧草稿**：编辑某个实例时，把鼠标停在那个零件上按 `Shift+A`：光标下的 Label Studio 旧
     标注以幽灵色显示（只显示，草稿本身永不被改），`Enter` 并入编辑层算一笔，`Esc` 只撤幽灵。
   - **提示点只属于当前零件、当前帧**：提交、`Esc`、撤销、换零件、换帧都会清空（第一个点给
     3 个候选，`C` 轮换）；手工改过 SAM 的结果之后 `C` 就不再轮换，状态栏会说明。

4. **`Enter` 提交**。会话判断这次编辑属于哪种范围：普通情况直接按 `keyframe` 写进去；若判断是
   **层次关系**而不是轮廓问题（你画的像素落在另一个实例的形状里），画布下方弹出一条**非模态**
   提示条，写明建议范围、会写什么、影响帧数，`Enter` 接受建议、`Alt+Enter` 只改这一帧、
   `Ctrl+K` 从这一帧起拆分。`Esc` 放弃这次编辑。

5. **`Space` 确认整帧**。通过了自动退到 k−1；没通过不动，问题列在任务卡里（比如某个应该在机箱
   里的实例还没有形状）。这一步还会把仍然"没人解释"的差异区域交给复查队列的 `unexplained`。

6. 中途想对比：**按住 `Tab`** 闪回任务卡对照的那一帧（j+1），松开回来，视角不动；`Shift+Tab` 闪回另一侧。

`Ctrl+Z` / `Ctrl+Y` 撤销重做，画笔笔画、SAM 应用、提交都在同一条历史里。

**不会丢东西的几条规矩**（都只在状态栏提示，不弹框）：

- 编辑层里有没提交的像素时，**下面每一件事都会被挡住**，并提示"未提交的修改：Enter 提交 /
  Esc 放弃"：`PgUp`/`PgDn`/`Home`/`End`、点时间轴、点复查队列、切视图、切机器、切模式、
  双击另一个实例、`Space` 确认（**包括任务卡上的 `Confirm  Space` 按钮**）、`F5`、复查里的
  `R` 返工、S1 `Apply` 后的重载、从 sidecar 恢复旧编辑、`Shift+R` 重画 ROI、`Ctrl+Shift+B`
  断开位姿段。按 `Enter` 或 `Esc` 之后再走；被挡住时 sidecar 会立刻落盘。
- 任务卡上的四个按钮和它们的键**完全等价**（`Commit ⏎` 也先问建议范围，不是一律 `keyframe`）。
- **没选中实例就开始画**：自动认领任务卡第一条没做完的"画形状"条目（状态栏写 `editing <实例>`）；没有可认领的，这一笔原样撤销并提示"先选一个实例"。
- 每一笔画完 0.3 秒后未提交的编辑层写进 sidecar（第 8 节），提交或 `Esc` 后自动删除；写不进去时状态栏挂着"崩溃保护已失效"，看到就尽快提交。

**平移画面**：**鼠标中键拖拽**（`Space` 是"确认整帧"），滚轮缩放，点右下角缩略图也能移过去。
**实例表**只列这一帧还在画面里的实例，勾 `Removed` 列出拆走的（灰色只读）。**按住 `Tab` 时画布是对照帧**，所有工具停用，状态栏写"正在对照 step N"。

## 4. 四种编辑范围，分别什么时候用

| 范围 | 键 | 含义 | 什么时候用 |
|---|---|---|---|
| `keyframe` | `Enter` | 改当前生效的关键帧，影响它覆盖的整段 | **默认**。零件的形状一直就是这样，只是之前画错了。 |
| `frame_override` | `Alt+Enter` | 只改这一帧 | 这一帧被手挡住了 / 有反光 / 这一帧特别糊，别的帧没问题。 |
| `split` | `Ctrl+K` | 从这一帧起产生新的一版形状 | 形状**真的**从这里开始变了：盖子打开、线束被拨到一边、风扇换了角度。 |
| `zorder:above:B` | `Enter` 接受建议 | 记录"A 盖住 B"，**并把你新画的像素写进 A 的形状** | 你往 B 上画了 A 的一块：那块本来就不在 A 的形状里，只改层级会把它丢掉。 |
| `split+zorder:above:B` | 建议出现时按 `Ctrl+K` | 同上，但形状是**从这一帧起的新版本**，层级照样记 | 形状真的从这里变了，而且新画的部分被 B 盖着。少了层级你会看到"提交了但画面没变"。 |
| `zorder:below:B` | `Enter` 接受建议 | 只记录"B 盖住 A"，**不缩小 A 的形状** | 你擦掉的正是 A、B 重叠处：A 那块还在，只是被 B 挡住了。 |

范围条写明三个键各自要写什么。选错了一次 `Ctrl+Z` 连层级带形状一起退回；**但**影响到已确认的帧会进冲突队列。

## 5. ROI（机箱范围）

第一次打开一个机器 / 视图 / 位姿段时，程序用 `suggest_roi` 自动框出机箱，
在画布上显示成可拖动的矩形：拖到合适，`Enter` 存进这一段的 `pose_segment.roi`。
之后 `F` 缩放到 ROI，`Shift+R` 重新框（编辑层里有未提交的像素时会被挡住）。
**ROI 框出现时 `Enter` / `Esc` 归它管**：存矩形 / 放弃矩形，都不动你的编辑层。
ROI 不只是取景：**帧间差异图只在 ROI 内算**（台面边缘的伪差异会淹没真变化），框歪了直接影响
SAM 的框提示质量。

## 5.5 位姿断点（`Ctrl+Shift+B`）

位姿段按视角独立：断点 = `reorient` 步（四视角共用）∪ **本视角自己的断点**。相机被碰过、机箱被
挪动过之后形状不能沿用，`Ctrl+Shift+B` 从当前帧起新开一段：对话框并排放上一帧和这一帧，写明有
几个形状跨过断点，勾选框决定要不要把它们复制到前一段（位移小于 25 px 默认勾上；不勾就让前面的
帧变成"缺形状"，提示你按新位姿重画；**手动断点永远不预勾**，因为你正是嫌形状对不上才断的）。
相机审计提议的断点会在该帧（仅标注模式）弹出提示条：`Tab` 对比两帧再按 接受 / 拒绝 —— 拒绝的
留在表里，下次导入不再提议；接受后再拒绝会把两段合并回去，这就是断点的撤销（`Ctrl+Z` 不管结构
性编辑；**断开后撤销历史清空**，先确认再断）。层级和成对覆盖会复制到新的一段；**两个 ROI 只有
实测位移小于 25 px 才复制**，190 px、90° 或手动断点的另一侧会重新弹 ROI 框请你确认。时间线上每
个已接受的断点画一条细横线；受影响的已确认帧进复查队列，形状一字节不改。合并时层级以"保留参考
帧那一段"为准（另一段独有的层追加到末尾，不会丢），换位置的层对与其余损失写进 `pose_issues`。

## 5.6 约束图（Steps 第三页 Relations）

这台机器的硬约束图（§7）。每行一条边，第一列**来源**决定你能做什么：`rule` 由实例属性推出，
每次 `constraints` 重新推导，**不能改删**，右键只有 接受 / 拒绝 —— 记录在案的决定，重跑照样
算数，再右键可撤销；`manual` 是你加的边，规则从不碰，重跑一字节不变，也只有它能删。

加边：下面一行选 从（目标）/ 类型 / 到（阻挡方）/ 强度 / 方式，写句理由，按 `Add edge`；只有
`blocked_by` 填方式。端点不存在或是 `ls:` 草稿、自环、与已有边重复、成环（提示里写明环）当场
拒绝并说明。

表下是 `constraints --validate` 的同一份校验：`missing edge?` 意思是"这步失败了，可图里没有拦
路的东西"，正是该补 `blocked_by` 的地方，补对了当场消失；双击跳到步骤表对应行。编辑全是暂存
的，和步骤表一起 `Apply`（同一事务；边集真变了才重盖 `graph_version`），`Revert` 丢掉。

## 6. 复查队列

Review 模式右侧四个标签页，页签上带数量：

- **Conflicts 冲突**：你的编辑和某个已冻结的帧对不上。选中后 `Keep old` 丢弃编辑、
  `Accept new` 接受编辑并重新冻结受影响的帧。这条冲突已被后来的改动**顶掉**时，程序说
  "已被覆盖，重新入队"并刷新 —— 不是拒绝，是让你看新的那条；真正被拒绝时理由写在状态栏。
- **Needs review 待复查**：标了需要第二双眼睛的帧。
- **Missing shape 缺形状**：编译器认为该有形状却没有的实例。
- **Unexplained 未解释差异**：确认帧时仍然没人认领的变化区域，通常意味着漏标了一个零件。

回车 = **打开选中条目的那一帧并确认它**（不是确认屏幕上这一帧）；`R` 退回重做。复查模式不自己扫全视图。

`F5` 只重新编译**当前这一帧**，并把失败/积压的复检**重新排队**（后台线程慢慢做，状态栏报
数量），按下去是瞬间的。整个视图的重新编译交给命令行：

```bat
D:\Anaconda\envs\tda\python.exe -m tda.cli check --desktop 13 --view scan
```

导出（`export-coco` / `export-vlm`）会先做同样的事情；只要还有帧排队等复检，导出就会拒绝，
并告诉你先跑 `check`。

## 8. 常见问题

**打不开，提示被锁住。**
`<db>.lock` 写着持有人和时间，对方关窗口就自动释放。崩溃留下的残留锁超过有效期后，下一次
`acquire_lock` 会自动接管；急用可以手动删掉 `D:\DataSet\annotations\tda.sqlite.lock`，
**前提是确认没有第二个人在标**。

**某一步没有图像。**
画布显示"本视图在该步骤没有图像"，工具全部禁用。这一逻辑步骤仍在时间轴上
（状态机和形状锚点都要经过它），只是这个视图没拍到。`PgUp` / `PgDn` 自动跳过它，在时间轴上点它才停在上面。

**提交之后出现冲突。**
说明这次编辑改变了某个已确认帧的结论。去 Review 的 Conflicts 队列按第 6 节处理，看不懂哪边对就 `Tab` 对比两帧。

**程序崩了，刚画的没提交。**
每一笔画完（停手 0.3 秒后）把编辑层写到 `D:\DataSet\.cache\sidecar\<你的名字>\`，按
"机器/视图/步骤/实例"分文件。下次打开同一帧或再次编辑该实例时，画布下方出现
"上次未提交的编辑可以恢复"，点 `恢复` 拿回来，`丢弃` 扔掉；实例已被 S1 删掉时记录自动清理。已提交的内容即时落盘，不会丢。

**内存卡扣、CPU 压杆跟着主板走。** 这两样长在主板上，日志只会 `open`，从不单独拆。程序按
"挂在主板上"处理：主板被拆走那一步它们一起离开机箱，之后任务卡不再要它们的形状（勾实例表的
`Removed` 能看到它们和主板一起灰着）；往回走到主板还在的那一帧，卡片写
`Draw ram_latch.01 (ram_latch) on this frame, back in with motherboard.01`，照画即可。
若某个卡扣其实不跟主板走，**去实例表取消勾选 `attached`、或把 `parent` 改指别处**：
只清空 `parent` 不算数，下次推断会把主板填回去。（主板一直没被拆走的机器，每一帧当然还要画。）

**任务卡让我画一个已经不在画面里的盖子。** 多数日志把这步写成 `open cover`，实际却是整个拿走
了，状态机只好按"打开但仍在机箱里"算，于是每帧都还要它。回 S1 步骤表把那一步的动词从 `open`
改成 `remove`，**改一处整条序列自动跟着变**。（`ram_latch` / `cpu_socket_lever` 的动词下拉框
里没有 `remove`，那是故意的：它们不靠动词离开。）

**SAM 用不了。** 状态栏写明原因（缺权重 / 没有 CUDA / 没装 `sam2`）；权重路径来自 `configs/paths.yaml` 的 `weights_dir`。画笔照样能标。

**想知道这台机器还差多少。**
顶部机器下拉框写着 `D13 <品牌> [已确认/总帧数]`，确认一帧、换视图或后台复检完成后立即更新；
命令行 `tda.cli status --desktop 13` 给分视图统计（`check` 见第 6 节）。
