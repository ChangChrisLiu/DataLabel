# Teardown Annotator 标注手册

面向每天标注 6 小时的人。全文假设你在 Windows 上、数据盘是 `D:`、原始数据盘 `F:` 只读。

---

## 1. 启动

```bat
rem 接着上次的机器和帧继续；也可以显式指定
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang --desktop 13 --view scan --step 42
```

- 只有 `--annotator` 必填（它同时是锁的持有人）。`--desktop` / `--view` / `--step` 省略时按
  `tda_app.ini` 里记的**你上次的机器、视图、步骤**打开；第一次用则打开有帧的最小编号机器的
  `scan` 视图，落在**最后一张有图像的帧**上（倒序标注从这里开始）。
- 启动时先取**单人锁**再打开数据库。别人正开着时会弹框写明持有人和时间，以退出码 3 退出，
  而数据库文件根本没有被打开过（只读了一次锁文件 `<db>.lock`）。
- SAM 在窗口显示**之后**才在后台线程里加载，第一帧 0.7 秒左右就能看到。没有模型（缺权重、
  没有 CUDA）不影响别的功能：状态栏写明原因，只是 `S` / `X` 两个工具不可用。
- 窗口大小、面板布局、上次的机器/视图/步骤存在 `D:\DataSet\.cache\tda_app.ini`，不写注册表、
  不写 C 盘；日志在 `D:\DataSet\.cache\logs\tda_app.log`。

**关闭时**，按这个顺序：先停后台线程（SAM 队列、差异图线程、模型加载线程）→ `session.save()`
→ `session.close()`（等自己的后台复检线程收尾）→ 备份数据库到 `paths.yaml` 的 `backup_dir`
并校验（文件存在且非空）→ 释放锁。备份失败只在状态栏告警，不拦着你关窗口。还有**没提交的
编辑**时会先弹一个框问你：提交 / 放弃 / 取消关闭。

## 2. 三种模式

顶部标签页切换，中间区域跟着换。**复查模式下画布是只读的**：不接任何工具，点画布只会提示
"按 R 返工"——因为在复查模式里开始的编辑没法提交（Enter/Esc 属于标注模式）。

| 模式 | 中间显示 | 什么时候用 |
|---|---|---|
| **Steps（S1 步骤核对）** | 步骤表 + 实例表 | 新机器第一步：核对步骤、动作、目标实例，拆分复合行，删掉没人引用的实例。`Apply` 之后会话在**同一帧**重新打开；有未保存修改时切走会先问一句。 |
| **Annotate（标注）** | 画布 | 主战场。倒序一帧一帧往前画。 |
| **Review（复查）** | 只读画布 + 右侧队列 | 冲突、待复查、缺形状、未解释差异。`Enter` 接受、`R` 返工、`K`/`N` 处理冲突。 |

## 3. 倒序标注一步的流程

标注方向和拆解方向相反：你从最后一帧往回走，也就是"把刚拆下来的零件一个个装回去"。
`PgDn` 是"前进"（k−1），`PgUp` 是后退。

**关键一点：任务卡说的永远是"你眼前这一帧要画什么"。**
站在第 j 帧时，卡片列的是第 j+1 帧到第 j 帧之间的变化 —— 那个在 j+1 已经被拆下、在 j 还装在
机箱里的零件，所以每一条都可以**就在当前这张图上**画出来并提交。按住 `Tab` 闪回的就是第 j+1
帧，`Shift+Tab` 闪回另一侧；差异图也是拿当前帧和 j+1 比的，高亮那块正是卡片让你画的零件重新
出现的位置。（若 j+1 在本视图缺帧会跳到再上一帧，状态栏会说明——这时卡片跨了不止一个动作。）

1. **看任务卡**（右上）。它由会话根据相邻两帧的状态差自动生成，每条写明要做什么：
   - ✚ `add_shape`：这个零件在 k−1 还在机箱里，要把它画回去；
   - ✂ `split_keyframe`：形状变了（盖子打开→关上、接头拔掉→插上），需要新的一版形状；
   - ≡ `state_only`：形状不变，只是状态变（螺丝拧松→拧紧），不用画；
   - ▭ `add_bench_box`：零件拆到台面上了，双击这条把框工具武装给它（不开编辑层）；没武装时
     `R` + 拖框只认**这一帧确实在台面上**的选中实例，换帧/视图/机器/模式/工具或 `Esc` 解除武装；
   - ⌫ `remove_bench_box`：零件回到机箱里了，它的台面框到此为止；
   - ✔ `confirm`：这一帧没什么可画的（重复帧、失败帧），一个键确认。
   已经做完的条目会被划掉，第一条没做的自动高亮。

2. **双击任务卡条目**开始编辑。它会把该实例当前的完整（amodal）形状读进编辑层，黄色高亮。

3. **画**。两条路，通常混着用：
   - **SAM**：按 `S` 用点提示。差异图会把"变化最大、且没有被别的条目解释掉"那块的外框自动喂给
     SAM（点 + 框，实测 IoU 0.76，只给一个点是 0.24），画面上有虚线框提示用的是哪块。
   - **手改**：`B` 画笔加像素、`E` 橡皮减像素，`[` `]` 调笔刷大小（可长按；非美式键盘上
     `[` `]` 可能要配合右 Alt，按不出来就用 `?` 查表里的键名）。`Shift+F` 填内部空洞，
     `Shift+D` 删小碎块，各算一次可撤销操作。
   - 手工改过 SAM 的结果之后 `C` 就不再轮换了（不会把你的修改丢掉），状态栏会说明。
   - **提示点只属于当前零件、当前帧**：提交、`Esc`、撤销、换零件、换帧都会清空，下一次点击
     永远是一个新的提示（第一个点给 3 个候选，`C` 轮换）。

4. **`Enter` 提交**。会话判断这次编辑属于哪种范围：普通情况直接按 `keyframe` 写进去；
   如果判断是**层次关系**而不是轮廓问题（你画的像素落在另一个实例的形状里），会在画布下方
   弹出一条**非模态**提示条，写明建议范围、会写什么、影响帧数，`Enter` 接受建议、
   `Alt+Enter` 只改这一帧、`Ctrl+K` 从这一帧起拆分。`Esc` 放弃这次编辑。

5. **`Space` 确认整帧**。通过了就自动退到 k−1；没通过不会动，问题列在任务卡里
   （比如某个应该在机箱里的实例还没有形状）。这一步还会把仍然"没人解释"的差异区域
   交给复查队列的 `unexplained`。

6. 中途想对比：**按住 `Tab`** 闪回任务卡对照的那一帧（j+1），松开回来，视角不动；
   `Shift+Tab` 闪回另一侧。

`Ctrl+Z` / `Ctrl+Y` 撤销重做，画笔笔画、SAM 应用、提交都在同一条历史里。

**不会丢东西的几条规矩**（都只在状态栏提示，不弹框）：

- 编辑层里有没提交的像素时，**下面每一件事都会被挡住**，并提示"未提交的修改：Enter 提交 /
  Esc 放弃"：`PgUp`/`PgDn`/`Home`/`End`、点时间轴、点复查队列、切视图、切机器、切模式、
  双击另一个实例、`Space` 确认（**包括任务卡上的 `Confirm  Space` 按钮**）、`F5`、
  复查里的 `R` 返工、S1 `Apply` 后的重载、从 sidecar 恢复旧编辑、`Shift+R` 重画 ROI。
  按 `Enter` 或 `Esc` 之后再走；被挡住时 sidecar 会立刻落盘。
- 任务卡上的四个按钮和它们的键**完全等价**（`Commit ⏎` 也会先问建议范围，不是一律 `keyframe`）。
- **没选中实例就开始画**：自动认领任务卡第一条没做完的"画形状"条目（状态栏写 `editing
  <实例>`）；没有可认领的，这一笔原样撤销并提示"先选一个实例"。
- 每一笔画完 0.3 秒后未提交的编辑层写到 `D:\DataSet\.cache\sidecar\<你的名字>\`，提交或
  `Esc` 后自动删除；写不进去时状态栏一直挂着"崩溃保护已失效"，看到它就尽快提交。

**平移画面**：**鼠标中键拖拽**（`Space` 是"确认整帧"），滚轮缩放，点右下角缩略图也能移过去。
**实例表**只列这一帧还在画面里的实例，勾 `Removed` 列出拆走的（灰色只读）。**按住 `Tab` 时画布上是对照帧**，所有工具停用，状态栏写"正在对照 step N"。

## 4. 四种编辑范围，分别什么时候用

| 范围 | 键 | 含义 | 什么时候用 |
|---|---|---|---|
| `keyframe` | `Enter` | 改当前生效的关键帧，影响它覆盖的整段 | **默认**。零件的形状一直就是这样，只是之前画错了。 |
| `frame_override` | `Alt+Enter` | 只改这一帧 | 这一帧被手挡住了 / 有反光 / 这一帧特别糊，别的帧没问题。 |
| `split` | `Ctrl+K` | 从这一帧起产生新的一版形状 | 形状**真的**从这里开始变了：盖子打开、线束被拨到一边、风扇换了角度。 |
| `zorder:above:B` | `Enter` 接受建议 | 记录"A 盖住 B"，**并把你新画的像素写进 A 的形状** | 你往 B 上画了 A 的一块：那块本来就不在 A 的形状里，只改层级会把它丢掉。 |
| `split+zorder:above:B` | 建议出现时按 `Ctrl+K` | 同上，但形状是**从这一帧起的新版本**，层级照样记 | 形状真的从这里变了，而且新画的部分被 B 盖着。少了层级你会看到"提交了但画面没变"。 |
| `zorder:below:B` | `Enter` 接受建议 | 只记录"B 盖住 A"，**不缩小 A 的形状** | 你擦掉的正是 A、B 重叠处：A 那块还在，只是被 B 挡住了。 |

范围条写明三个键各自要写什么。选错了一次 `Ctrl+Z` 连层级带形状一起退回；**但**影响到已确认的帧会进冲突队列。

## 5. ROI（机箱范围）

第一次打开一个机器 / 视图 / 位姿段时，程序会用 `suggest_roi` 自动框出机箱，
在画布上显示成一个可拖动的矩形：拖到合适，`Enter` 存进这一段的 `pose_segment.roi`。
之后 `F` 缩放到 ROI，`Shift+R` 重新框（编辑层里有未提交的像素时会被挡住）。
**ROI 框出现时 `Enter` / `Esc` 归它管**：存矩形 / 放弃矩形，都不动你的编辑层。
ROI 不只是取景：**帧间差异图只在 ROI 内计算**（扫描仪台面边缘的伪差异会淹没真正的变化），
所以框歪了会直接影响 SAM 的框提示质量。

## 6. 复查队列

Review 模式右侧四个标签页，页签上带数量：

- **Conflicts 冲突**：你的编辑和某个已冻结的帧对不上。选中后 `Keep old` 丢弃编辑、
  `Accept new` 接受编辑并重新冻结受影响的帧。如果这条冲突已经被后来的改动**顶掉**了，程序会说
  "已被覆盖，重新入队"并刷新队列 —— 这不是拒绝，是让你看新的那条；真正被拒绝时理由写在状态栏。
- **Needs review 待复查**：标了需要第二双眼睛的帧。
- **Missing shape 缺形状**：编译器认为该有形状却没有的实例。
- **Unexplained 未解释差异**：确认帧时仍然没人认领的变化区域，通常意味着漏标了一个零件。

回车 = **打开选中条目的那一帧并确认它**（不是确认屏幕上这一帧）；`R` 退回重做。复查模式不自己扫全视图。

`F5` 只重新编译**当前这一帧**，并把失败/积压的复检**重新排队**（后台线程慢慢做，状态栏报
数量），按下去是瞬间的。整个视图的重新编译交给命令行：

```bat
D:\Anaconda\envs\tda\python.exe -m tda.cli check --desktop 13 --view scan
```

导出（`export-coco` / `export-vlm`）会先做同样的事情；只要还有帧排队等复检，导出就会拒绝，
并告诉你先跑 `check`。

## 8. 常见问题

**打不开，提示被锁住。**
`<db>.lock` 里写着持有人和时间。对方关窗口就会自动释放。
如果那是崩溃留下的残留锁，超过有效期后下一次 `acquire_lock` 会自动接管；
急用可以手动删掉 `D:\DataSet\annotations\tda.sqlite.lock`，**前提是确认没有第二个人在标**。

**某一步没有图像。**
画布会显示"本视图在该步骤没有图像"，工具全部禁用。这一逻辑步骤仍然留在时间轴上
（状态机和形状锚点都要经过它），只是这个视图没拍到。`PgUp` / `PgDn` 会自动跳过它，
在时间轴上点它才会停在上面。

**提交之后出现冲突。**
说明这次编辑改变了某个已确认帧的结论。去 Review 的 Conflicts 队列，
按上面第 6 节处理。看不懂哪边对就 `Tab` 对比两帧图像。

**程序崩了，刚画的没提交。**
每一笔画完（停手 0.3 秒后）都会把编辑层写到 `D:\DataSet\.cache\sidecar\<你的名字>\`，按
"机器/视图/步骤/实例"分文件。下次打开同一帧、或再次编辑同一个实例时，画布下方会出现一条
"上次未提交的编辑可以恢复"，点 `恢复` 拿回来，点 `丢弃` 扔掉；那个实例在这一帧已经不存在
（S1 里删掉了）时这条记录会被自动清理。已提交的内容每次操作即时落盘，不会丢。

**SAM 用不了。** 状态栏会写明原因（缺权重文件 / 没有 CUDA / 没装 `sam2`）；权重路径来自
`configs/paths.yaml` 的 `weights_dir`。其余功能不受影响，用画笔照样能标。

**想知道这台机器还差多少。**
顶部机器下拉框里写着 `D13 <品牌> [已确认/总帧数]`，确认一帧、换视图或后台复检完成后会立即更新；
命令行 `python -m tda.cli status --desktop 13`
给更细的分视图统计，`python -m tda.cli check --desktop 13 --view scan` 重新编译并列出问题。
