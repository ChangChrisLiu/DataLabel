# Teardown Annotator 标注手册

面向每天标注 6 小时的人。全文假设你在 Windows 上、数据盘是 `D:`、原始数据盘 `F:` 只读。

---

## 1. 启动

```bat
D:\Anaconda\envs\tda\python.exe -m tda.cli app --desktop 13 --view scan --annotator chang
```

- `--desktop` 机器编号，`--view` 视图（`scan` / `oak1` / `oak2` / `rs`），`--annotator` 你的名字。
- `--step K` 可以直接打开某一逻辑步骤；不给就落在**最后一张有图像的帧**上（倒序标注从这里开始）。
- 启动时程序会取**单人锁**。如果别人正开着，会弹框写明持有人和时间，然后以退出码 3 退出，
  数据库一个字节都不会动。等对方关掉，或确认那是残留的锁文件（`<db>.lock`）再重试。
- SAM 模型在窗口显示**之后**才在后台线程里加载，所以第一帧 2 秒内就能看到。
  没有模型（缺权重、没有 CUDA）不影响别的功能：状态栏会写明原因，只是 `S` / `X` 两个工具不可用。
- 窗口大小、停靠面板布局、上次打开的机器/视图/步骤存在 `D:\DataSet\.cache\tda_app.ini`，
  不写注册表、不写 C 盘。日志在 `D:\DataSet\.cache\logs\tda_app.log`。

**关闭时**：会话保存 → 数据库备份到 `paths.yaml` 的 `backup_dir` 并校验（文件存在且非空）→ 释放锁。
备份失败只会在状态栏告警，不会拦着你关窗口。

---

## 2. 三种模式

顶部标签页切换，中间区域跟着换。

| 模式 | 中间显示 | 什么时候用 |
|---|---|---|
| **Steps（S1 步骤核对）** | 步骤表 + 实例表 | 新机器第一步：核对日志解析出来的步骤、动作、目标实例，拆分复合行，删掉没人引用的实例。改完按 `Apply`。 |
| **Annotate（标注）** | 画布 | 主战场。倒序一帧一帧往前画。 |
| **Review（复查）** | 画布 + 右侧复查队列 | 冲突、待复查、缺形状、未解释差异四个队列。 |

- 在 Steps 模式里 `Apply` 之后，会话会在**同一帧**上重新打开（实例和状态事件都变了）。
- Steps 模式有未保存的修改时切走会先问一句。

---

## 3. 倒序标注一步的流程

标注方向和拆解方向相反：你站在第 k 帧，往第 k−1 帧走，也就是"把刚拆下来的零件装回去"。
`PgDn` 是"前进"（k−1），`PgUp` 是后退。

1. **看任务卡**（右上）。它由会话根据 k 和 k−1 的状态差自动生成，每条写明要做什么：
   - ✚ `add_shape`：这个零件在 k−1 还在机箱里，要把它画回去；
   - ✂ `split_keyframe`：形状变了（盖子打开→关上、接头拔掉→插上），需要新的一版形状；
   - ≡ `state_only`：形状不变，只是状态变（螺丝拧松→拧紧），不用画；
   - ⌫ `remove_bench_box`：零件回到机箱里了，它的台面框到此为止；
   - ✔ `confirm`：这一帧没什么可画的（重复帧、失败帧），一个键确认。
   已经做完的条目会被划掉，第一条没做的自动高亮。

2. **双击任务卡条目**开始编辑。它会把该实例当前的完整（amodal）形状读进编辑层，黄色高亮。

3. **画**。两条路，通常混着用：
   - **SAM**：按 `S` 用点提示。差异图会把"这一帧和上一帧之间变化最大、且没有被别的条目解释掉的
     区域"的外框自动喂给 SAM（点 + 框，实测 IoU 0.76，只给一个点是 0.24）。
     画面上会有一个虚线框提示它用的是哪块。没有框可用时单点会返回 3 个候选，`C` 轮换。
   - **手改**：`B` 画笔加像素、`E` 橡皮减像素，`[` `]` 调笔刷大小。
     `Shift+F` 填内部空洞，`Shift+D` 删小碎块。这两个都算一次可撤销操作。
   - 手工改过 SAM 的结果之后 `C` 就不再轮换了（不会把你的修改丢掉），状态栏会说明。

4. **`Enter` 提交**。会话会判断这次编辑属于哪种范围：
   - 普通情况直接按 `keyframe` 写进去；
   - 如果判断是**层次关系**而不是轮廓问题（你画的像素落在另一个实例的形状里），
     会在画布下方弹出一条**非模态**提示条，写明建议范围和影响帧数，
     `Enter` 接受建议、`Alt+Enter` 只改这一帧、`Ctrl+K` 从这一帧起拆分。
   - `Esc` 放弃这次编辑。

5. **`Space` 确认整帧**。通过了就自动退到 k−1；没通过不会动，问题列在任务卡里
   （比如某个应该在机箱里的实例还没有形状）。这一步还会把仍然"没人解释"的差异区域
   交给复查队列的 `unexplained`。

6. 中途想对比：**按住 `Tab`** 闪回上一步的图像，松开回来，视角不动。

`Ctrl+Z` / `Ctrl+Y` 撤销重做，画笔笔画、SAM 应用、提交都在同一条历史里。

## 4. 四种编辑范围，分别什么时候用

| 范围 | 键 | 含义 | 什么时候用 |
|---|---|---|---|
| `keyframe` | `Enter` | 改当前生效的关键帧，影响它覆盖的整段 | **默认**。零件的形状一直就是这样，只是之前画错了。 |
| `frame_override` | `Alt+Enter` | 只改这一帧 | 这一帧被手挡住了 / 有反光 / 这一帧特别糊，别的帧没问题。 |
| `split` | `Ctrl+K` | 从这一帧起产生新的一版形状 | 形状**真的**从这里开始变了：盖子打开、线束被拨到一边、风扇换了角度。 |
| `zorder:*` | `Enter` 接受建议 | 记录"A 在 B 之上"，不动像素 | 你画的其实是"这块应该盖住那块"，不是轮廓不对。会话会主动建议。 |

选错了不要紧：`Ctrl+Z` 撤销，重来。**但**如果影响到已经确认过的帧，会产生冲突进复查队列。

## 5. ROI（机箱范围）

第一次打开一个机器 / 视图 / 位姿段时，程序会用 `suggest_roi` 自动框出机箱，
在画布上显示成一个可拖动的矩形：拖到合适，`Enter` 存进这一段的 `pose_segment.roi`。
之后 `F` 缩放到 ROI，`Shift+R` 重新框。

ROI 不只是取景：**帧间差异图只在 ROI 内计算**（扫描仪台面边缘的伪差异会淹没真正的变化），
所以框歪了会直接影响 SAM 的框提示质量。

## 6. 复查队列

Review 模式右侧四个标签页，页签上带数量：

- **Conflicts 冲突**：你的编辑和某个已冻结的帧对不上。选中后 `Keep old` 丢弃编辑、
  `Accept new` 接受编辑并重新冻结受影响的帧。
  如果这条冲突已经被后来的改动**顶掉**了，程序会说"已被覆盖，重新入队"并刷新队列 ——
  这不是拒绝，是让你看新的那条。真正被拒绝时会把理由原样写在状态栏。
- **Needs review 待复查**：标了需要第二双眼睛的帧。
- **Missing shape 缺形状**：编译器认为该有形状却没有的实例。
- **Unexplained 未解释差异**：确认帧时仍然没人认领的变化区域，通常意味着漏标了一个零件。

回车确认当前帧，`R` 把它退回重做。
`F5` 重新编译整个视图（几秒到几十秒，进度在状态栏），队列不会自己偷偷做这件事。

## 8. 常见问题

**打不开，提示被锁住。**
`<db>.lock` 里写着持有人和时间。对方关窗口就会自动释放。
如果那是崩溃留下的残留锁，超过有效期后下一次 `acquire_lock` 会自动接管；
急用可以手动删掉 `D:\DataSet\annotations\tda.sqlite.lock`，**前提是确认没有第二个人在标**。

**某一步没有图像。**
画布会显示"本视图在该步骤没有图像"，工具全部禁用。这一逻辑步骤仍然留在时间轴上
（状态机和形状锚点都要经过它），只是这个视图没拍到。`PgUp` / `PgDn` 会自动跳过它，
在时间轴上点它才会停在上面。

**提交之后出现冲突。**
说明这次编辑改变了某个已确认帧的结论。去 Review 的 Conflicts 队列，
按上面第 6 节处理。看不懂哪边对就 `Tab` 对比两帧图像。

**程序崩了，刚画的没提交。**
每一笔画完都会把编辑层写到 `D:\DataSet\.cache\sidecar\`。
下次打开同一帧同一实例时，画布下方会出现一条"上次未提交的编辑可以恢复"，
点 `恢复` 拿回来，点 `丢弃` 扔掉。已提交的内容本来就每次操作即时落盘，不会丢。

**SAM 用不了。**
状态栏会写明原因（缺权重文件 / 没有 CUDA / 没装 `sam2`）。
权重路径来自 `configs/paths.yaml` 的 `weights_dir`。其余功能不受影响，用画笔照样能标。

**想知道这台机器还差多少。**
顶部机器下拉框里写着 `D13 <品牌> [已确认/总帧数]`；命令行 `python -m tda.cli status --desktop 13`
给更细的分视图统计，`python -m tda.cli check --desktop 13 --view scan` 重新编译并列出问题。
