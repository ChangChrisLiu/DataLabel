# Teardown Annotator 标注手册

面向每天标注 6 小时的人。全文假设 Windows、数据盘 `D:`、原始盘 `F:` 只读。

---

## 1. 启动

```bat
rem 接着上次的机器和帧继续；也可以显式指定
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang
D:\Anaconda\envs\tda\python.exe -m tda.cli app --annotator chang --desktop 13 --view scan --step 42
```

- 只有 `--annotator` 必填（也是锁的持有人）。其余省略时按 `tda_app.ini` 记的**上次机器 /
  视图 / 步骤**开；第一次用开有帧的最小编号机器 `scan` 的**最后一张有图像的帧**。
- 先取**单人锁**再开数据库。别人开着时弹框写明持有人和时间，以退出码 3 退出，数据库没被
  打开过（只读了锁文件 `<db>.lock`）。
- SAM 在窗口显示**之后**才后台加载，第一帧 0.7 秒就能看到；没模型只是 `S` / `X` 不可用（§8）。
- 窗口大小、面板布局也在 `.cache\tda_app.ini`，日志在 `.cache\logs\tda_app.log`（都在
  `D:\DataSet` 下，不写注册表和 C 盘）。

**关闭时**依次：停后台线程 → `session.save()` → `session.close()`（等复检收尾）→ 备份到
`backup_dir` 并校验非空 → 放锁。备份失败只告警，不拦关窗口；有**没提交的编辑**时先弹框问：
提交 / 放弃 / 取消。

## 2. 窗口和三种模式

从左到右：时间轴、**工具面板**、画布、右侧 **「现在做什么」** + 任务卡 + 实例表。

- **工具面板**：每个工具和提交 / 确认 / 撤销键各一个按钮，**点按钮 = 按那个键**（标签从同一张
  键表生成）。深色底黄字 = 当前工具（和状态栏黄标签同一状态）；蓝框 = 下一步最该按的；灰掉的，
  鼠标停上去说为什么。笔刷大小在中间：滑块、数字框、`[` `]` 是同一个数（图像像素）。
- **「现在做什么」**：黄底一行写下一步按什么；下面 ①–⑤ 是这一帧的五步，▶ 是当前这步；折叠的
  「快捷键」只列这个模式能用的键。

顶部标签页切模式。**复查模式下画布只读**：不接工具，点画布只提示"按 R 返工"。

| 模式 | 中间显示 | 什么时候用 |
|---|---|---|
| **Steps（S1 步骤核对）** | 步骤表 + 实例表 + 约束图 | 核对步骤 / 动作 / 目标实例，拆分复合行，删没人引用的实例，补约束边（§5.6）。`Apply` 后会话在**同一帧**重开；有未保存修改时切走会先问。 |
| **Annotate（标注）** | 画布 | 主战场。倒序一帧帧往前画。 |
| **Review（复查）** | 只读画布 + 右侧队列 | 四个队列见第 6 节。`Enter` 接受、`R` 返工、`K`/`N` 处理冲突。 |

## 3. 倒序标注一步的流程

从最后一帧往回走，等于"把刚拆下的零件一个个装回去"；`PgDn` 是"前进"（k−1）。每一步做什么、
按什么，「现在做什么」面板都写着；这里只记规则。

**任务卡永远说"眼前这一帧要画什么"**：第 j 帧列的是在 j+1 已拆下、j 还装着的零件，所以每条都
**就在这张图上**画。卡片顶上一句说这张清单是什么；每条写中文名、实例键、日志里的名字、一句要做
什么和状态（待画 / ✎ 正在画 / ✔ 已完成）。`Tab` 闪回 j+1，差异图也拿 j+1 比（缺帧时跨过去，
状态栏会说）。图标（标题提示里有）：✚ 画回去；✂ 形状变了，`Ctrl+K` 提交；≡ 只是状态变，不用画；
▭ 在台面上，单击这条把台面框武装给它（没武装时 `R` 只认这一帧确实在台面上的选中实例）；⌫ 台面框
到此为止；✔ 这帧没东西可画，直接 `Space`。鼠标停在一条上，画面用虚线框标出它大概在哪（它上一帧
的形状 / 差异最大处 / 旧草稿），只显示，不改任何状态。

1. **单击条目**开始编辑（双击也行）：画布顶上出现"正在画：…"横幅。层是空的，工具自动切到上次
   用的 SAM 工具（没用过是 SAM 点选；SAM 没加载就不动）；按住画笔直接在画布上画，则认领卡片
   第一条没做完的"画形状"条目，工具不变。
2. **画**：
   - **SAM**：`S` 点、`X` 框。差异图把"变化最大、又没被别的条目解释"那块的外框喂给 SAM（点+框
     实测 IoU 0.76，单点 0.24），虚线框标出是哪块；框不对 `Shift+C` 换（第 1 个永远是默认那块）。
     **只做加法**：再点再框都**并**进层里，不抹掉手画的、采纳的，也不把擦掉的加回来；减像素只有
     `E` 和右键负点。提示点只属于当前零件、当前帧；第一个点给 3 个候选，`C` 轮换。
   - **手改**：`B` / `E`，`Shift+F` 填洞、`Shift+D` 删碎块，各算一笔。
   - **旧草稿**：鼠标停在零件上按 `Shift+A`，光标下的旧标注以幽灵色显示：`Enter` 并入，`Esc` 撤。
3. **`Enter` 提交**：普通情况按 `keyframe`；判断是**层次关系**（像素落进别的实例形状）时画布下方
   弹非模态提示条，`Enter` 接受、`Alt+Enter` 只改这一帧、`Ctrl+K` 从这帧起拆分，`Esc` 放弃。
4. **`Space` 确认整帧**：通过就退到 k−1；没通过不动，问题列在任务卡下面。仍"没人解释"的差异区
   交给复查队列 `unexplained`。

`Ctrl+Z` / `Ctrl+Y` 撤销重做，笔画、SAM、提交在同一条历史里。

**不会丢东西的规矩**（只在状态栏提示，不弹框）：

- 编辑层有没提交的像素时，**每一件离开这一帧的事都会被挡住**（翻页、时间轴、复查队列、切视图 /
  机器 / 模式、点另一实例、`Space` 及其按钮、`F5`、复查 `R`、S1 `Apply`、恢复 sidecar、
  `Shift+R`、`Ctrl+Shift+B`），提示"Enter 提交 / Esc 放弃"；被挡住时 sidecar 立刻落盘。
- 面板和任务卡上的按钮与键**完全等价**（「提交」也先问建议范围）。
- 每一笔画完 0.3 秒后编辑层写进 sidecar（§8），提交或 `Esc` 后删；写不进时状态栏挂"崩溃保护已
  失效"。

**平移**：中键拖拽，滚轮缩放。**实例表**勾 `Removed` 看拆走的（只读）。**按住 `Tab`** 画布是
对照帧，工具全停。

## 4. 四种编辑范围，分别什么时候用

| 范围 | 键 | 含义 | 什么时候用 |
|---|---|---|---|
| `keyframe` | `Enter` | 改当前生效的关键帧，影响它覆盖的整段 | **默认**。零件的形状一直就是这样，只是之前画错了。 |
| `frame_override` | `Alt+Enter` | 只改这一帧 | 这一帧被手挡住了 / 有反光 / 这一帧特别糊，别的帧没问题。 |
| `split` | `Ctrl+K` | 从这一帧起产生新的一版形状 | 形状**真的**从这里开始变了：盖子打开、线束被拨到一边、风扇换了角度。 |
| `zorder:above:B` | `Enter` 接受建议 | 记录"A 盖住 B"，**并把你新画的像素写进 A 的形状** | 你往 B 上画了 A 的一块：那块本来就不在 A 的形状里，只改层级会把它丢掉。 |
| `split+zorder:above:B` | 建议出现时按 `Ctrl+K` | 同上，但形状是**从这一帧起的新版本**，层级照样记 | 形状真的从这里变了，而且新画的部分被 B 盖着。少了层级你会看到"提交了但画面没变"。 |
| `zorder:below:B` | `Enter` 接受建议 | 只记录"B 盖住 A"，**不缩小 A 的形状** | 你擦掉的正是 A、B 重叠处：A 那块还在，只是被 B 挡住了。 |

范围条写明三个键各写什么。选错了 `Ctrl+Z` 连层级带形状退回；**但**影响已确认帧会进冲突队列。

## 5. ROI（机箱范围）

第一次打开一个机器 / 视图 / 位姿段时，程序自动框出机箱，**等你回答**，画布下方的提示条写明
它是什么、干什么、怎么答。它不只是取景：**差异图和 SAM 提示框都只在框内算**（台面边缘的伪
差异会淹没真变化），画面也按它缩放。

- 拖四角 / 四边的白方块改大小（光标会变），框里按住移动，空白处拖动重画，框外压暗的不算。
  **框开着时 `Enter` / `Esc` 归它管**，都不动编辑层；太小的框和整幅图都不会存下。
- **`Enter` 存**进 `pose_segment.roi`；**`Esc` 跳过** —— 矩形收起，问题还在：提示条留一行
  `ROI 未确认` 带 `确认建议框` / `重画 Shift+R` / `不用 ROI`，不挡操作也不再自己弹，换视图
  回来还在。**`不用 ROI`** 才是"这段不要框"的答案（重切位姿段会重新问）。
- 状态栏常驻 `ROI ✓` / `ROI 未确认` / `无 ROI`；存好的框画成细虚线，同 `A` 开关，`F` 缩放到
  它，`Shift+R` 重画（编辑层脏时挡）。

## 5.5 位姿断点（`Ctrl+Shift+B`）

位姿段按视角独立：断点 = `reorient` 步（四视角共用）∪ **本视角的断点**。相机被碰过、机箱挪过
之后形状不能沿用，`Ctrl+Shift+B` 从当前帧起新开一段：对话框并排放两帧，写明几个形状跨过断点，
勾选框决定要不要复制到前一段（位移 < 25 px 默认勾上；不勾前面的帧就变"缺形状"，提示按新位姿
重画；**手动断点永远不预勾**，你正是嫌形状对不上才断的）。相机审计提议的断点在该帧（仅标注
模式）弹提示条：`Tab` 对比两帧再按 接受 / 拒绝 —— 拒绝的下次导入不再提议；接受后再拒绝会
合并回去，这就是断点的撤销（`Ctrl+Z` 不管结构性编辑；**断开后撤销历史清空**，先确认再断）。
层级和成对覆盖复制到新一段；**两个 ROI 只有实测位移 < 25 px 才复制**，190 px、90° 或手动断点
的另一侧会重新弹 ROI 框。时间线上每个已接受的断点画一条细横线；受影响的已确认帧进复查队列，
形状一字节不改。合并时层级以"保留参考帧那段"为准（另一段独有的层追加
末尾，不丢），换位置的层对与其余损失写进 `pose_issues`，状态栏只给条数。

## 5.6 约束图（Steps 第三页 Relations）

这台机器的硬约束图（§7）。每行一条边，第一列**来源**决定你能做什么：`rule` 由实例属性推出，
每次 `Apply`/`constraints` 重推，**不能改删**，右键只有 接受 / 拒绝 —— 决定存成同一条边的
`override` 行，重跑照样算数，再右键可撤销；`manual` 是你写的边，重跑不变，也只有它能删。
规则不再推出那条边时决定变 `*_orphan`（失效），右键 保留为手动边（写理由）/ 清除。

加边：选 从（目标）/ 类型 / 到（阻挡方）/ 强度 / 方式，写句理由，`Add edge`。只有 `blocked_by`
填方式，它决定挡什么：`cable_tension` 只挡 remove，`physical_path` 还挡 displace，
`tool_access` 全挡。端点不存在或是 `ls:` 草稿、自环、与已有边重复、**required** 边造成**死锁**
（一圈动作互相等，谁都做不了；不是零件成环）的编辑当场拒绝并写明那圈动作；`recommended` 只是
顺序偏好，矛盾了提示一句、规划时忽略。

表下是 `constraints --validate` 的同一份校验，外加死锁/死路检查（都进"待确认问题"，双击跳到
那条边；死锁标红拦 Apply，**死路**只提醒：某条边没有动作能解除，多半缺零件）。
`missing edge?` 是"这步失败了，图里却没拦路的东西"，正是该补 `blocked_by` 的地方，补对当场
消失，双击跳到步骤表那行。编辑暂存，和步骤表一起 `Apply`（同一事务，连规则重推；边集真变了
才重盖 `graph_version`）。改实例表可能让规则边复活并和手动边死锁：**这种 Apply 整个拒绝并
回滚**，按提示删/改手动边或拒绝那条规则边；`Revert` 全丢掉。

## 6. 复查队列

Review 模式右侧四个标签页，页签上带数量：

- **Conflicts 冲突**：你的编辑和某个已冻结帧对不上。`Keep old` 丢弃编辑、`Accept new` 接受并
  重新冻结受影响的帧。被后来的改动**顶掉**的冲突说"已被覆盖，重新入队"并刷新（不是拒绝，是
  让你看新的那条）；真被拒绝时理由在状态栏。
- **Needs review 待复查**：要第二双眼睛的帧。
- **Missing shape 缺形状**：编译器认为该有形状却没有的实例。
- **Unexplained 未解释差异**：确认帧时没人认领的变化区域，多半漏标了零件。

回车 = **打开选中条目那一帧并确认它**（不是屏幕上这帧）；`R` 退回重做。复查不扫全视图。

`F5` 只重编译**这一帧**并把失败/积压的复检**重新排队**（后台做，状态栏报数量），按下去是
瞬间的。整视图交给命令行：

```bat
D:\Anaconda\envs\tda\python.exe -m tda.cli check --desktop 13 --view scan
```

导出（`export-coco` / `export-vlm`）先做同样的重编译；还有帧排队等复检就拒绝，叫你先跑 `check`。

## 8. 常见问题

**打不开，提示被锁住。**
`<db>.lock` 写着持有人和时间，对方关窗口就释放；崩溃残留的锁过期后下次启动自动接管，
急用可手动删，**前提是确认没有第二个人在标**。

**某一步没有图像。**
画布写"本视图在该步骤没有图像"，工具全禁用。这一逻辑步骤仍在时间轴上（状态机和形状锚点都要
经过），只是这个视图没拍到；翻页自动跳过，点时间轴才停。

**提交之后出现冲突。**
这次编辑改变了某个已确认帧的结论，去 Review 的 Conflicts 按§6 处理。

**程序崩了，刚画的没提交。**
每一笔画完把编辑层写到 `.cache\sidecar\<你的名字>\`，按"机器/视图/步骤/实例"分文件。下次打开
同一帧或再编辑该实例时画布下方出现"上次未提交的编辑可以恢复"，`恢复` 拿回来、`丢弃` 扔掉；
实例已被 S1 删掉时自动清理。已提交的内容即时落盘。

**内存卡扣、CPU 压杆跟着主板走。** 它们长在主板上，日志只会 `open`，从不单独拆，程序按
"挂在主板上"处理：主板被拆走那步它们一起离开机箱，任务卡不再要形状（勾 `Removed` 能看到它们
和主板一起灰着）；往回走到主板还在的那帧，卡片写"（跟 motherboard.01 一起装回来的）"（提示里是
`Draw ram_latch.01 (ram_latch) on this frame, back in with motherboard.01`），照画即可。
某个卡扣不跟主板走时，**去实例表取消 `attached` 或把 `parent` 改指别处**：只清空 `parent`
不算数，下次推断会把主板填回。（主板没拆走的机器每帧照画。）

**任务卡让我画一个已经不在画面里的盖子。** 多数日志把这步写成 `open cover`，实际整个拿走了，
状态机只好按"打开但仍在机箱里"算，于是每帧都还要它。回 S1 把那步动词改成 `remove`，**改一处
整条序列跟着变**。（`ram_latch` / `cpu_socket_lever` 的动词框里没有 `remove` 是故意的：它们
不靠动词离开。）

**SAM 用不了。** 状态栏写明原因（缺权重 / 没有 CUDA / 没装 `sam2`）；权重路径来自
`paths.yaml` 的 `weights_dir`。

**想知道还差多少。**
顶部机器下拉框写着 `D13 <品牌> [已确认/总帧数]`，确认一帧、换视图或后台复检后即更新；
`tda.cli status --desktop 13` 给分视图统计。
