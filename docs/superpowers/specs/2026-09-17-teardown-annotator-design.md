## 0. 摘要

构建一个运行在本工作站（RTX 5090 / 63 GB / Windows 11）上的 **PySide6 本地一体化标注工具**，为 66 台台式机拆解序列生成：实例掩码（可见 + 近似完整形状）、零件状态、步骤动作、物理约束图，并程序化导出 COCO 与 VLM 训练/评测数据。核心思路：

1. **倒序 + 图层模型**做传播：从拆解末帧往回标，每步只"装回"发生变化的零件，下层可见区域自动计算。
2. **真值是逐帧物化并人工确认的掩码表**，图层模型只是生成器；后续修改绝不静默覆盖已确认的帧。
3. **扫描仪俯视为主视角**（身份、状态、差分在它上面判定），OAK 相机1 继承身份后精标，OAK 相机2 以预标 + 核验为主。
4. **结构化标注是唯一事实来源**，VLM 文本全部由它生成，答案可程序校验。
5. **约束 = 物理必要性**，由属性规则 + 机型族模板生成、人工确认；实际拆解顺序只用于校验。

## 1. 目标、范围与优先级

### 1.1 目标

- **CV**：三视角实例分割/检测（23 类 + 属性），含小零件（螺丝、卡扣、接口）；状态识别。
- **约束**：每台机器一张带物理原因的约束图，可计算任一状态下的合法动作集合。
- **VLM**：看到了什么、零件状态、刚做了什么、现在能做什么、下一步、指代定位（P0），为什么不能、剩余规划、工具（P1）。
- **可报告的质量**：逐帧确认率、双标一致性、模型辅助效率（初稿 vs 终稿）。

### 1.2 范围

**v1 包含**：66 台机器 Disassemble 序列（约 2,830 步）× {扫描仪, OAK1, OAK2}。

**v1 不包含**：Components / Side view 文件夹、房间视频、128 张单反照片、RealSense 标注、机器人数据、网页界面、多人同时在线。

### 1.3 优先级

| 级别 | 内容 |
|---|---|
| **P0** | 扫描仪 gold（66 台）；步骤/动作/状态；约束图；COCO 导出与检测/分割基线；VLM V1/V2/V3/V5/V6/V8 + 零样本评测 |
| **P1** | OAK1 gold（先测试划分）；OAK2 silver（先测试划分）；VLM V4/V7/V9、人类基线、微调一个开源 VLM |
| **P2** | OAK2 全量精修；OAK1 RGB-D 对齐导出（可在数据冻结后计算）；LLM 改写问答；SAM 3；多模型预标对比；SAM 解码器微调；超像素贴边 |

### 2.1 源数据

| 视角 | 源路径（F: 只读） | 每步使用的文件 |

| OAK 相机1 `oak1` | `OAKD Capture\...\Desktop N\Disassemble\Camera_1\NNN\*_rgb_12mp.jpg`（4032×3040） | 12MP 图；另记录 `rgb_aligned.png`、`depth_raw.npy` 路径供导出 |

| 拆解记录 | Google Drive 每台一张表，正式导入时存入 `D:\DataSet\raw_logs\` | 步骤名、dupli、工具、机型元数据 |

### 2.2 统一索引

- **帧键**：`(desktop_id, step_k, view)`；`step_k` 是**逻辑步**，以 OAK 相机1 拍摄时间戳顺序为准。
- **对齐规则**：OAK1/OAK2 按文件名时间戳配对；扫描仪按 `RGB<step>1` 编号 + 文件时间对齐到最近的 OAK 步；Drive 记录按行序（含 dupli）对齐。
- **已知异常修复规则**（写成 `configs/index_fixes.yaml`，可审阅）：
  - D60：相机2 文件夹错位；相机1 第 003/004 步时间顺序颠倒；
  - D42：相机2 016/017 对调；
  - D24：相机2 末步被放入 Components；
  - D10：第 1 步重拍（保留后一次）；
  - 扫描仪：D1 缺 10 步、11 台缺末步、约 50 个步骤只有 9 张连拍；
  - D66 仅 13 步。
- **记录与相机步数不一致**（D1 −1、D43 −1、D56 跳号 41、D63 11–13 重号）：进入"待人工确认"清单，在步骤表界面逐条处理。
- **缺帧**：某视角缺某步时该帧标记 `missing`，但逻辑步、状态与形状锚点照常存在（§4.2）。

### 2.3 步骤表导入

- 每行生成 `Step`（原始名、dupli、原始工具、备注）。
- 从原始名解析出 0..n 个 `Action` 草稿：目标（实例或虚拟节点）、动词、工具（§6 映射）。
- 步骤类型：`initial`（第 1 步，0 动作）、`dupli`（0 动作，整帧复制）、`compound`（≥2 动作）、`failed`（有动作、无状态变化）、`auxiliary`（挪开障碍物以露出目标，目标可以是虚拟节点 `cable:*`）、`reorient`（翻转机箱，触发位姿断开）、`ignore`（如 "all components (final layout)"，不属于拆解序列）。

### 2.4 本地缓存与 ROI

- **缓存**：所需图像复制到 `D:\DataSet\cache\<view>\D<nn>\s<kkk>.<ext>`（约 26 GB）。扫描仪 1600² 直接使用；OAK 12MP 在 P1 阶段生成 ROI 裁剪缓存与金字塔。
- **扫描仪选图**：在 10 连拍中排除曝光无效（均值/饱和比例超阈值）与**偏离连拍中值过大**（手入镜）的图，再取清晰度（拉普拉斯方差）最高者；记录分数，可人工改选。
- **ROI**：每台机器每个视角框一次机箱区域（自动建议 + 人工确认）。**掩码一律按原图坐标存储**，ROI 只是显示与推理窗口。

### 2.5 几何

- **帧内配准（同视角相邻步）**：
  - **MVP（扫描仪）**：恒等变换；机箱被翻转由步骤类型 `reorient` 或人工标记触发位姿断开。
  - **P1**：RANSAC 估计相对位姿段参考帧的相似变换（天然排除本步变化区域的外点），超过阈值（扫描仪 2 px、OAK 3 px）才应用；**不做链式累积**；残差可视化给人确认。
  - 位姿断开：开启新位姿段，该段形状重新绘制，实例 ID 沿用。
- **跨视角（扫描仪 → OAK1/OAK2，P1）**：每台机器每个视角每个位姿段人工点 4 个机箱角点，估计到扫描仪的单应；**只传递实例中心点作为 SAM 提示与身份候选，不传递掩码**。
- **OAK 12MP ↔ 1280×800 对齐图（P2）**：逐台用特征匹配估计"缩放 + 裁剪"并检验是否恒定；导出 RGB-D 掩码时使用，截断帧标记。

## 3. 数据模型

### 3.1 实体

| 实体 | 关键字段 |
|---|---|
| `Desktop` | id、品牌、机型族、机箱平台、机箱类型、尺寸、日期、划分、备注 |
| `Instance` | `instance_key`（如 `screw.cpu_cooler.03`）、类别（§6）、属性（role、head、kind、captive…）、`parent`、原始名列表；**接口**另有 `socket_host`（插在哪个实例/虚拟节点上）与 `cable_owner`（线缆固定连在哪个部件上：PSU、机箱前面板、机箱风扇、CPU 风扇；独立线缆为空） |
| `VirtualNode` | 不画掩码的节点：`chassis_front_panel`、`cable:<描述>` 等；线缆节点有状态 routed / released |
| `Step` | k、类型（§2.3）、原始名、dupli、备注 |
| `Action` | step、目标（实例或虚拟节点）、动词、工具、方向（§6.4）、结果（success/failed） |
| `StateEvent` | 目标、step、旧值→新值；由 `Action` 自动生成（含父零件移除时附着子零件的连带事件），可手工补 |
| `TrackingPolicy` | 类别 × 状态 → 是否需要掩码（默认见 §6.2），可按实例覆盖 |
| `Frame` | 帧键、源文件、扫描仪选图、位姿段、变换 `T_k`、标记（手/工具入镜、模糊、missing）、审核状态（未标 / 自动 / 已确认 / 需复核） |
| `PoseSegment` | 视角、起止步、参考帧、到扫描仪的单应 |
| `ShapeKeyframe` | 实例、视角、位姿段、**`anchor_step`（该形状适用的最晚逻辑步）**、形状部件列表（每部件一张 RLE，参考帧坐标）、`amodal_complete`、来源（手画/SAM/模型@版本）、初稿引用 |
| `ZOrder` | (视角, 位姿段) 下 (实例, 部件) 的全序，带版本号 |
| `PairOverride` | (视角, 位姿段, A, B)：A 在 B 之上，优先于全序 |
| `OccluderMask` | 帧级遮挡层（手、手臂、身体、工具），只作用于当前帧 |
| `FrameOverride` | (实例, 帧)：替换可见掩码，或 `hidden`（本视角不可见）。**所有"只改这一帧"的编辑都写到这里** |
| `CompiledMask` | 真值表（§3.4） |
| `Relation` | §7 |
| `Op` | 源操作日志（撤销/重做、审计） |

### 3.2 实例身份

- **身份由步骤表决定**：`instance_key` = 类别 + 角色 + 同类序号（按首次被操作的逻辑步排序），不依赖记录中的编号。
- **图像中"哪一颗是 3 号"**：MVP 在扫描仪上叠加第 k−1/k 帧差分热图由人点选；P1 起自动把本步目标匹配到变化斑块。不脱落螺丝差分弱时人工点选。
- **三视角同一身份**：第 k 步变化的实例在三个视角是同一物体；OAK 视角用跨视角单应投影扫描仪实例中心作为提示。

### 3.3 编译器（纯函数、可单测）

对视角 v、逻辑步 k：

1. `state(k)` = 初始状态 + 所有 step ≤ k 的事件（父零件 `removed` 时，`attached` 的子零件自动 `removed`）。
2. `needs_mask(k)` = 状态不为 `removed`、且 `TrackingPolicy` 要求掩码的实例（例如 `unplugged` 的接口不需要）。
3. 对每个 `i ∈ needs_mask(k)`：在同一位姿段内取 **`anchor_step ≥ k` 中最小者**对应的关键帧（关键帧 j 适用于 (上一个锚点, anchor_j]）。若不存在 → `missing_shape`，该帧不可确认。
4. 形状经 `T_k`（最近邻）变换到帧坐标 → `A_i`。
5. `V_i = A_i − ∪{A_j : j 在 i 之上}`，逐对判断：有 `PairOverride` 用它，否则用 `ZOrder`（逐对判断，环不会导致错误）。多部件实例按部件分别参与。
6. `V_i = V_i − OccluderMask_k`；若有 `FrameOverride`，以其为准（`hidden` 则无可见掩码）。
7. 输出 `V_i`、`A_i` 引用与**输入哈希**（关键帧版本、z 序版本、覆盖、变换、遮挡层、状态事件版本、编译器版本）。

**关键帧与标注方向**：
- 实例寿命由步骤表预先确定，因此首次绘制时默认锚点 = 该实例在本位姿段内最后一个需要掩码的逻辑步。
- 在第 j 步"拆分关键帧"时，新形状作用于**当前浏览方向**一侧：倒序时新关键帧锚点 = j（适用于更早的步）；正序时原关键帧锚点改为 j−1、新关键帧继承原锚点。

### 3.4 真值表 `CompiledMask`

| 字段 | 说明 |
|---|---|
| 键 | (desktop, view, step, instance) |
| `visible_rle` | 可见掩码（原图坐标） |
| `status` | `auto`（随输入刷新）/ `verified`（整帧确认后冻结） |
| `input_hash`、`verified_by`、`verified_at` | 溯源 |

规则：

- 输入变化时，只刷新 `auto` 行。
- 冻结行的重编译结果与冻结值比较：**容差对称差**（忽略两者边界 2 px 以内的差异）> max(2% 面积, 20 px) → 生成冲突，进入冲突队列（保留旧值 / 接受新值 / 编辑），**绝不静默覆盖**；否则保留冻结值。
- 向已确认帧新增实例（如补漏一颗螺丝）或删除实例 → 该帧降为"需复核"。
- 导出只读 `CompiledMask`，报告 verified 比例；gold 视角只导出 verified 帧。

### 3.5 存储

- SQLite（WAL 模式）：`D:\DataSet\annotations\tda.sqlite`；RLE 为 pycocotools 格式。
- 备份：每日与每次退出时用 SQLite backup API 备份到 `F:\PHD Data Backup\Desktop Dataset\TDA_backups\`（14 天滚动 + 每周快照）。
- 单用户锁文件（当前标注员与时间）。

## 4. 标注流程与界面

### 4.1 每台机器的工作单

| 阶段 | 内容 | 预计耗时 |
|---|---|---|
| S0 自动准备 | 索引、缓存、扫描仪选图、ROI 建议、步骤表草稿、差分热图 | 无人工 |
| S1 步骤与实例核对 | 每行显示扫描仪第 k−1/k 帧缩略图，预填动作/目标/工具；实例表填父零件、`socket_host`、`cable_owner`、角色、头型 | 已有模板：10–15 min；机型族首台：30–45 min |
| S2 扫描仪倒序标注（gold） | §4.2 | 2–2.5 h |
| S3 OAK1 迁移 + 精修（gold，P1） | 4 角点单应 → 中心点提示 → SAM → 编辑 → 审阅确认 | 1–1.3 h |
| S4 OAK2 预标 + 核验（silver，P1） | 预标 + SAM 框精修 → 逐帧核验实例与状态，只修明显错误 | 0.5 h |
| S5 约束图 | 规则/模板实例化 → 接受/拒绝 → 校验（§7） | 已有模板：10 min；首台：30 min |
| S6 质检与冻结 | 自动检查全部通过、冲突清零、标记完成 | 5–10 min |

**按机型族分批**：先做大族（OptiPlex 7020 ×11、HP Compaq 8200 Elite ×8、OptiPlex 7010 ×6、EliteDesk 800 G1 ×6），首台建立约束模板后同族复用。

### 4.2 倒序标注（S2/S3）

1. **起点** = 该视角最后一个可用帧（不一定是空机箱）；在起点帧画出所有需要掩码的实例。
2. **从第 k 帧退到第 k−1 帧**时，任务卡列出动作 k 引起的变化：
   - `removed → installed`：新增形状，默认放最上层；**同时列出随它一起装回的附着子零件**（如不脱落螺丝），逐个确认形状；
   - `open → closed`、`unplugged → plugged`、`displaced → installed`：在 k−1 处拆分关键帧（新形状作用于更早的步）；`unplugged → plugged` 时接口从"不追踪"变为需要掩码，直接新画；
   - `loosened → fastened`：只改状态，形状沿用；
   - `dupli`：整帧复制，一键确认；`failed`：无状态变化，一键确认。
3. 画布叠加差分热图；点击 → SAM（在原分辨率裁剪窗推理）→ 编辑 → Enter。
4. 处理差分中未被任何事件解释的明显区域：拆分关键帧 / 画遮挡层 / 标记忽略。
5. 空格确认本帧 → 写入 `verified` → 下一帧。

**缺帧处理**：
- 扫描仪缺第 k 步时，S2 跳过该帧的掩码，但状态事件与关键帧锚点仍按逻辑步计算。
- S3 中，对没有扫描仪对应帧的步，OAK1 回退为原生倒序标注（无中心点提示，身份由步骤表与 OAK1 差分确定）。

### 4.3 编辑语义

每次像素编辑必须明确作用范围，画布下方显示"影响 N 帧"缩略条：

| 范围 | 含义 | 默认触发 |
|---|---|---|
| **改形状关键帧** | 修改当前生效的关键帧，影响其适用区间内所有未冻结帧 | 编辑像素不落在其他实例形状内 |
| **改层级** | 写 `PairOverride` | 画笔加像素落入 B 的形状 → 提示"把 A 放到 B 之上？"；橡皮擦掉 A 中与 B 重叠的像素 → 提示"把 B 放到 A 之上？" |
| **单帧覆盖** | 写 `FrameOverride`，只改这一帧 | 按住 `Alt` |
| **拆分关键帧** | 从当前步起按浏览方向生成新版本（§3.3） | `Ctrl+K` |

- 画笔/橡皮/顶点编辑**绝不触发模型重推理**。
- 会影响已冻结帧的修改，先提示"将产生 N 个冲突"。

### 4.4 审阅模式

- 逐帧浏览（上下键），显示可见掩码轮廓、状态标签、问题列表；Enter 接受整帧、`R` 标记返工。
- 入口：冲突队列、需复核队列、缺形状队列、未解释变化队列。

### 4.5 界面布局

## 5. 模型辅助

### 5.1 交互式分割（MVP）

- **SAM 2.1 Hiera-L** 图像预测器常驻后台线程；输入为视野裁剪窗（原分辨率）；支持点、框、`mask_input`。
- 显存预算：SAM 约 4–6 GB，其余留给训练。
- SAM 3 概念提示（如 "screw"）列为 P2 试验。

### 5.2 训练闭环（P1，约 8–10 台扫描仪 gold 后启用）

- 只接一个框架：**Ultralytics YOLO26-seg**。
- 训练数据：已确认的 ROI 裁剪 + 可见掩码；每新增约 10 台重训，子进程运行，限制批大小避免与 SAM 争显存。
- 用途：起点帧提议、OAK1 提议、OAK2 预标；预测框交给 SAM 精修边界后成为可编辑初稿。
- **OAK2 冷启动**：前 3–4 台 OAK2 用 SAM + 角点单应中心点提示人工完成，加入训练集后再对 OAK2 批量预标（扫描仪训练的模型对斜视角域差大）。
- 多框架对比（RF-DETR-Seg、EoMT/Mask2Former）只作论文基线，不进入标注闭环。

### 5.3 效率记录

- 每个形状保存初稿与终稿，记录初稿 IoU、编辑操作数、耗时，用于论文报告模型辅助效率。

### 5.4 精度目标

- 边界误差：扫描仪 ≤ 2 px，OAK ≤ 3 px（在双标机器上测量）。
- 螺丝头型等属性优先取 Drive 工具列或扫描仪判读。

| 动词 | 适用 | 状态效果 |
|---|---|---|
| `unscrew` | screw | captive = true → loosened；否则 → removed |

## 7. 约束关系

### 7.1 定义

约束边表达**物理必要性**：对目标执行 `remove` / `displace` / `open`（及对螺丝 `unscrew`、对接口 `disconnect`）之前，另一节点必须处于指定状态。节点可以是实例或虚拟节点。

| 类型 | 语义 | 所需状态 |
|---|---|---|
| `fastened_by(X, screw)` | 螺丝不再固定 X | screw ∈ {loosened, removed} |
| `connected_to(X, connector)` | 由规则生成（见下） | connector ∈ {unplugged, removed} |
| `locked_by(X, latch)` | 锁扣已打开 | latch ∈ {open} |
| `covered_by(X, Y)` | 覆盖物已打开或移走 | Y ∈ {open, removed, displaced} |
| `blocked_by(X, Y)` | 另一部件或线缆物理阻挡 | Y ∈ {removed, displaced, released} |

**接口规则**：移除部件 X 之前，所有满足 `socket_host = X` **或** `cable_owner = X` 的接口必须已断开。
- 例：SATA 数据线（`cable_owner` 为空），SSD 端 `socket_host = SSD` → 取 SSD 只需拔 SSD 端，主板端不构成约束。
- 例：PSU 的 24pin（`cable_owner = PSU`，`socket_host = motherboard`）→ 取 PSU 和取主板都要求它已拔下。

- `occluded_by`（来自图像层级）是软关系，只作候选，不自动成为约束。
- 不使用 `partner_of`；同组由共同父零件表达。

### 7.2 生成

1. **属性规则**（预计覆盖约 90%）：子螺丝 → `fastened_by`；接口规则 → `connected_to`；`ram_latch.of = X` → `locked_by`；`cover.of` → `covered_by`；固定模板边（如 `cpu covered_by cpu_cooler`、`cpu locked_by cpu_socket_lever`）。
2. **机型族模板**：同族共享"零件槽位图"，实例化到每台机器；每个族的首台人工补全后保存为模板。
3. **人工**：剩余 `blocked_by`（含线缆虚拟节点）在约束面板添加。

每条边记录：来源（rule / template / manual）、证据（步骤 id）、状态（proposed / accepted / rejected）。

### 7.3 校验

- 图无环。
- 每个成功动作执行前一刻，其前置条件全部满足（否则缺边或标错）。
- 每次失败尝试执行前一刻，至少一个前置条件未满足，**包括虚拟线缆节点**（D35/D36 等因线缆失败的情况）。
- "合法动作集合"为计算量，不存储。

## 9. 质量控制

### 9.1 自动检查（S6 必须全部通过）

- 每个动作的目标存在；状态变化合法（removed 之后不再出现等）。
- 每个需要掩码的实例在 gold 视角有生效形状，或 `hidden`。
- 同一帧可见掩码两两不重叠。
- 冲突、需复核、未解释变化队列清零。
- 约束图无环；观察序列合法；失败尝试有未满足约束。
- dupli 帧与前一帧掩码一致（免费的一致性检验）。

### 9.2 人工质检与上手

- **标注指南**：`docs/annotation_guide.md`，含编辑语义、状态定义、常见情况示例（从 D13 截图）。
- **同学上手**：先独立标 D13 扫描仪视角，与用户版本比较，掩码 IoU ≥ 0.9、状态一致率 ≥ 95% 后进入生产标注。
- **双标**：4–5 台（覆盖 Dell/HP、SFF/塔式）扫描仪视角两人独立完整标注，报告掩码 IoU、状态 κ、约束边 F1。
- 每台完成后在审阅模式抽查 5 帧。

### 11.2 标注容量

- 需求（全量）：扫描仪 gold 130–160 h；S1/S5 约 40 h（含各族首台 +10 h）；OAK1 gold 70–90 h；OAK2 silver 30–40 h；双标约 10 h；同学上手约 5 h。合计约 285–355 h。
- 10/1–11/3 约 4.7 周。P0 需求（扫描仪 gold + S1/S5 + 双标 + 上手）约 185–215 h；再加测试划分（约 13 台）的 OAK1 gold + OAK2 silver 约 20–25 h → 约 205–240 h。
- **情形 A（用户每周 25–35 h + 同学生产标注每周 10–12 h）**：合计约 165–220 h → **与需求基本持平、偏紧**；P0 可以完成，测试划分的 OAK 视角取决于实际速度；训练划分的 OAK1/OAK2 大概率只能部分完成。
- **情形 B（同学只做审阅）**：约 120–165 h → 扫描仪 gold 只能覆盖约 40–50 台；剩余机器需改为 silver（模型预标 + 核验）或减少机器数，**需重新讨论**。
- **执行顺序**（即降级规则）：
  1. 测试划分机器：扫描仪 gold + 约束图（10/1 起）→ OAK1 gold（10/8 起）→ OAK2 silver（10/22 起）；
  2. 其余机器：扫描仪 gold + 约束图，按机型族分批；
  3. 双标 4–5 台；
  4. 剩余时间：训练划分补 OAK1，再补 OAK2 silver。
- **检查点**：10/15 统计实际单台耗时；若扫描仪单台 > 2.5 h，训练划分的 OAK1 全部降为 silver。

## 13. 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 继续使用 Label Studio / CVAT / X-AnyLabeling | 按单图设计，无法表达跨步继承、图层、共享实例、状态与约束 |
| 本地网页应用 | 开发量更大，两人轮流使用时收益不足 |
| 每帧独立掩码 | 遮挡需逐帧人工处理，无近似完整形状与自动遮挡关系 |
| 以图层模型本身作为真值 | 修改会静默改变已确认帧 |
| 关键帧使用显式 [a, b] 区间 | 倒序时下界未知，插入需同时改两条记录，易产生缝隙 |
| 链式相邻配准 | 漂移累积会静默污染整段 |
| 按接口"端点"生成约束 | 会把 SATA 线两端都变成约束（实际是"或"关系） |
| 追踪拔下的接口 | 插头随线缆移动，逐帧追踪代价极高而收益低 |
| 52 类细粒度词表 | 样本不足；状态应为属性 |
| 以实际拆解顺序作为约束真值 | 只是合法顺序之一 |
